# 06. The player app (`apps/player`, `@gog/player`)

Expo SDK 58, React Native 0.88, New Architecture, Expo Router with typed routes, development builds (ADR 0008). TypeScript strict; `exactOptionalPropertyTypes` is off for the app only (`@gog/tsconfig/expo.json`) because Expo Router, React Navigation and expo-image declare optional props without `| undefined`, so app code may pass `undefined` to optional props (`<Stack.Screen options={{ title: maybeString }} />`, `<Image source={cafe.imageUrl} />`) without conditional spreads. State: TanStack Query for server state, React context for session, local component state otherwise. Styling: React Native `StyleSheet` with a `theme.ts` (colours, spacing, radii, type scale) mirroring the website's dark palette. Images: `expo-image`.

## Data and session

- `src/lib/env.ts`: Zod-validated `process.env.EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY` (refined with `isPublishableKey` from `@gog/data/client`: a service-role key or a user token fails at startup, ADR 0011), `EXPO_PUBLIC_DATA_SOURCE` (`supabase | fixtures`, default `supabase`), `EXPO_PUBLIC_SITE_URL`, plus a literal `process.env.NODE_ENV` read. Release bundles refuse `fixtures` (ADR 0012): Expo inlines `NODE_ENV` as `production` in every release bundle (EAS `preview` and `production`, `expo run --configuration Release`, `expo export`, `expo start --no-dev`), so, unlike the website (whose gate is NODE_ENV and VERCEL_ENV, letting Vercel previews use fixtures), an EAS `preview` bundle is indistinguishable from `production` at runtime and both refuse it. If demo builds on fixtures are wanted later, that is an ADR 0012 amendment adding `EXPO_PUBLIC_ALLOW_FIXTURES=true` via `build.preview.env` in `eas.json`, not something to add now. The check runs inside the bundle at app start, so it makes the mistake loud in development and in any launched build, but the key is already inlined in that build's JavaScript; a pre-bundle gate (a small JavaScript check in `app.config.ts` or a `scripts/` step before `expo export` / EAS build, since Node cannot import TypeScript from `@gog/data` there) is a follow-up.
- `src/lib/clock.ts`: the one clock the app reads (`createServerClock` from `@gog/data/client`, exposed as `clock` and `nowIso()`). Every hold expiry, lead-time check and countdown compares a server-issued instant with "now", so the device clock is corrected by the `Date` header of every Supabase response (`createNativeClient({ clock })` routes requests through `clock.fetch`); on fixtures the device clock stands and the in-memory repository reads the same clock. `src/lib/useNow.ts` offers it as state refreshed on a timer for screens that derive lists from the time.
- `src/lib/supabase.ts`: `createNativeClient` from `@gog/data/client` with a storage adapter and the app clock. Follow Supabase's current Expo guide for the storage choice (AsyncStorage or `expo-sqlite/kv-store`) and for whether `react-native-url-polyfill` is still needed on RN 0.88; also call `supabase.auth.startAutoRefresh()` / `stopAutoRefresh()` on `AppState` changes as the guide shows.
- `src/lib/repositories.ts`: `catalog`, `booking`, `auth` built once via `@gog/data/factory` from env; the fixture source is given `now: clock.now`.
- `src/features/<area>/`: `queries.ts` (query keys and hooks: `useCafes`, `useCafe`, `useAvailability`, `useMyBookings`, mutations `useCreateHold`, `useConfirm`, `useCancel`) and components used only by that feature. Screens in `app/` stay thin: compose hooks and components, no business logic.
- `src/providers/SessionProvider.tsx`: subscribes to `AuthGateway.onAuthStateChange`, exposes `session`, `signOut`, and a `requireSession()` helper that opens the sign-in modal and resolves with the session once signed in, or with `null` when the sheet is dismissed ("Not now"), so a caller such as "Hold seats" stops instead of waiting forever. It sits inside `QueryProvider` and removes every `bookings` query whenever the session becomes null or the user id changes, so another account's holds are never shown to the next sign-in on the same phone (the default `staleTime` would otherwise serve them for 30 s).
- Errors: `BookingError.code` → user copy in `src/features/booking/copy.ts` (`limit_reached` names the caps from `BOOKING_RULES`); `seat_conflict` auto-retried by the data layer, so the UI shows "Those seats were just taken, pick another time" only if it still fails. Sign-in copy lives in `src/features/auth/copy.ts`: a `DataError` with code `transport` reads as a connection problem, an `auth` refusal as a wrong number or code.
- Phone entry: `src/features/auth/phone.ts` normalises what was typed or autofilled (`+91 98765 43210`, `098765 43210`, `9876543210` all become the ten local digits, prefixes stripped before the cap) and `PhoneForm` has no `maxLength`, so OS autofill with the country code is not truncated.

## Deep links

- `scheme: "gog"`; iOS `associatedDomains: ["applinks:<SITE_HOST>"]` and Android `intentFilters` with `autoVerify` for `https://<SITE_HOST>/cafes/*`, both built from `EXPO_PUBLIC_SITE_URL` in `app.config.ts`. The Android filter is `pathPrefix: '/cafes/'`, with the trailing slash: `pathPrefix` is a literal string prefix, so `/cafes` would also claim the website's `/cafes` list page and `/cafes?area=…`, which have no screen in the app.
- Expo Router maps `/cafes/[slug]` (web URL shape) to `cafe/[slug]` with a redirect route file `app/cafes/[slug].tsx` that `Redirect`s, so website URLs open the right screen; `app/cafes/index.tsx` redirects a stray `/cafes` or `/cafes/` link to Explore instead of "That screen does not exist".

## Configuration

- `app.config.ts` (not `app.json`): `name`, `slug: "gog-player"`, `scheme`, `version`, `orientation: "portrait"`, `userInterfaceStyle: "dark"`, `ios.bundleIdentifier` and `android.package` from env with placeholders `com.gog.player`, `ios.supportsTablet: false`, `android.adaptiveIcon`, `plugins: ["expo-router", ["expo-splash-screen", {...}]]` (no `expo-secure-store` in iteration 1: AsyncStorage holds the player's access and refresh tokens unencrypted inside the app sandbox, as Supabase's Expo guide defaults to; acceptable for the development build and to be revisited before public launch, ADR 0011, with Supabase's SecureStore adapter, `expo-secure-store` + `aes-js` + `react-native-get-random-values`), `experiments.typedRoutes: true`, `extra.eas.projectId` placeholder. The brand colours it needs for the icon, splash and native backgrounds come from `src/lib/palette.json`, shared with `theme.ts` and `scripts/make-assets.mjs`, because Node evaluates this file and cannot import TypeScript. Deep-link entries (`ios.associatedDomains`, `android.intentFilters`) are emitted only when `EXPO_PUBLIC_SITE_URL` is an https URL; a local http URL yields the `gog://` scheme alone.
- `eas.json`: `development` (`developmentClient: true`, `distribution: "internal"`, iOS simulator true), `preview` (`distribution: "internal"`), `production` (`autoIncrement: true`).
- `metro.config.js`: `getDefaultConfig(__dirname)`; add `watchFolders` / `nodeModulesPaths` for the workspace root only if the Expo monorepo guide still requires it for hoisted pnpm; keep it minimal and commented.
- `babel.config.js` only if the SDK requires one (SDK 58 does not for Expo Router; check).
- `.env.example` with the `EXPO_PUBLIC_*` variables.
- Assets: a plain generated icon, adaptive icon and splash (solid colour with the wordmark) in `assets/`; no third-party artwork.

Scripts: `start` (`expo start --dev-client`), `ios` (`expo run:ios`), `android`, `lint`, `typecheck` (`expo customize tsconfig.json && tsc --noEmit`: typed routes exist only after Expo writes `.expo/types/router.d.ts` and `expo-env.d.ts`, the same pattern as the website's `next typegen`), `test` (`vitest run`, Node environment, `src/**/*.test.ts`: the pure helpers only, phone normalisation, day and slot layout and booking history; screens and components stay covered by typecheck and lint, ADR 0010), `doctor` (`expo-doctor`; invoke it as `pnpm --filter @gog/player run doctor`, because `pnpm doctor` without `run` is pnpm's own command), `assets` (`node scripts/make-assets.mjs`). The ESLint config is `eslint.config.mjs` because the app is CommonJS for Metro (spec 04).

## Acceptance

- `pnpm --filter @gog/player typecheck`, `lint`, `test` and `doctor` pass. `npx expo export --platform ios` (bundle only) succeeds, proving Metro resolves the workspace packages (bundling does not execute the environment check).
- In the development build with `EXPO_PUBLIC_DATA_SOURCE=fixtures`, Explore shows the 6 sample cafes and the booking flow completes against the in-memory booking repository (hold → confirm) without a backend. A release bundle refuses `fixtures` at startup (Data and session).
- Opening `gog://cafe/pixel-den-koramangala` lands on that cafe.
- No `@supabase/supabase-js` import anywhere in app code (lint enforces; `src/lib/supabase.ts` goes through `@gog/data/client`).
