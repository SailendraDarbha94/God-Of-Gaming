5. The lint, typecheck and test step stays as it is: with `next.config.ts`'s presence rules limited to builds where `VERCEL_ENV` is set (`05-partner-app.md`), `@gog/partner#typecheck` runs `next typegen` with no data-source variables, which turbo's strict environment mode would not pass to it anyway.

`database` job:

1. 2. "Contract tests for the Supabase repositories": the must-pass loop becomes `for suite in booking/supabase-booking catalog/supabase-catalog partner/supabase-partner`. The persona phone variables need no setting, because their defaults match `config.toml`. With `GOG_TEST_SUPABASE_URL` set, the data package runs its test files one after another (`04-packages.md`, Contract suites), so the step takes longer than today.

## Integration and review

As in iteration 1: after the parts of a milestone are built, one integration step applies the builders' notes, reconciles the lockfile, runs this definition of done, and records the result; then a code review of the integrated tree, whose confirmed findings are fixed before the milestone merges. The review of M0 and M1 pays particular attention to the hazards ADR 0015 closes and to ADR 0014's rule that only a session opened with an SMS code, on a confirmed phone, carries a partner or operator role. The reviews of M2, M4 and M5 check the lock order, so that no two paths can deadlock and no check races the change it guards: `create_booking` keeps taking the user lock before the tier lock, and repeats its hours and closure checks after taking it; `set_station_active` takes its tier's lock, and `set_cafe_hours` and `add_cafe_closure` take every tier lock of the cafe in tier-id order, each before its conflict check; a function that locks a booking row and also takes the tier lock (`extend_counter_block`, `move_booking_seat`) locks the row first, and that row is always a confirmed booking; under the tier lock, a function changes only the booking it already holds, that booking's seats, lapsed holds (the lazy expiry) and the rows it inserts; `remove_cafe_member`, `set_cafe_member_role` and `delete_my_account` lock the cafe's owner rows (`for update`) before counting owners, and take no tier lock.
