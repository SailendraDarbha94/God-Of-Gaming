# 03. Database (`supabase/`)

Postgres 17 under Supabase. Everything below lives in `supabase/migrations/*.sql` (timestamped `20261104HHMMSS_name.sql`, applied in order), `supabase/seed.sql`, `supabase/tests/*.sql` (pgTAP) and `supabase/local/` (no-Docker shim). `supabase/config.toml` is created with `supabase init` and edited as noted at the end.

Conventions: snake_case; `uuid` primary keys with `gen_random_uuid()`; `created_at timestamptz not null default now()` and `updated_at` maintained by a `set_updated_at()` trigger on every table that has it; money as `integer` paise; instants as `timestamptz`; every table has RLS enabled in the same migration that creates it; functions set `search_path = public, extensions` explicitly; comments on tables and columns for anything non-obvious.

## Extensions

`btree_gist` (exclusion constraint) is created `with schema extensions`. `pg_cron` (hold-expiry sweeper) is created `with schema pg_catalog` (its control file pins that schema; its tables and functions live in the `cron` schema it creates), followed by `grant usage on schema cron to postgres; grant all privileges on all tables in schema cron to postgres;` as the Supabase docs show. Both `create extension if not exists` statements run inside a `DO` block that checks `pg_available_extensions`, because the Homebrew shim database lacks `pg_cron`.

## Enums

`station_kind` (`pc, ps5, xbox, switch, vr, sim_racing, other`), `cafe_status` (`draft, live, paused`), `booking_status` (`held, confirmed, cancelled, expired, completed, no_show`), `booking_source` (`app, counter`), `cafe_member_role` (`owner, staff`).

## Views

`cafe_cards` (`with (security_invoker = true)`): one row per cafe with `id, slug, name, status, city_slug, city_name, area_slug, area_name, cover_image_url` (lowest `sort_order`), `kinds station_kind[]` (distinct tier kinds, ordered), `from_hourly_rate_paise` (min over tiers that have at least one active station), `station_count` (active stations). Because it is security-invoker, RLS on `cafes` hides non-live rows automatically.

`booking_details` (`with (security_invoker = true)`): `bookings.*` plus `seats jsonb` = `coalesce((select jsonb_agg(jsonb_build_object('station_id', bs.station_id, 'station_label', bs.station_label, 'released_at', bs.released_at) order by bs.station_label) from booking_seats bs where bs.booking_id = b.id), '[]'::jsonb)`. Security-invoker, so the `bookings` policy applies to direct reads; inside the security-definer functions the owner reads it unrestricted. Clients read bookings only through this view (never by embedding `cafes`, `station_tiers` or `stations` from `bookings`, whose own RLS would null out refs to paused cafes or retired stations).

## Functions

All `language plpgsql`, `set search_path = public, extensions`. Errors use `raise exception ... using errcode = 'GGnnn'` with a short English message; clients map codes, never messages.

| SQLSTATE | Meaning                                                                     |
| -------- | --------------------------------------------------------------------------- |
| `GG001`  | authentication required (`auth.uid()` is null)                              |
| `GG002`  | invalid request (duration, seats, alignment, lead time); message says which |
| `GG003`  | outside opening hours                                                       |
| `GG004`  | not enough free seats                                                       |
| `GG005`  | seat conflict under concurrency; safe to retry once                         |
| `GG006`  | cafe not bookable (not live, or tier does not belong to cafe)               |
| `GG007`  | not found or not permitted                                                  |
| `GG008`  | invalid state transition                                                    |
| `GG009`  | booking limit reached (live holds or upcoming bookings)                     |

- `cafe_open_window(p_cafe_id uuid, p_day date) returns tstzrange` — `stable`, `security invoker`. Reads `cafe_hours` for `extract(dow from p_day)`, builds the IST window (`Asia/Kolkata`), adds a day to the close when `is_overnight`. Returns `null` when closed.
- `cafe_is_open_during(p_cafe_id uuid, p_starts timestamptz, p_ends timestamptz) returns boolean` — `stable`. Let `d = (p_starts at time zone 'Asia/Kolkata')::date`, `r = tstzrange(p_starts, p_ends, '[)')`, `w_today = cafe_open_window(p_cafe_id, d)` and `w_yesterday = cafe_open_window(p_cafe_id, d - 1)` (the previous day's overnight window). Returns `coalesce(r <@ w_today, false) or coalesce(r <@ w_yesterday, false)`, so it is `false`, never `null`, when both windows are `null`, and `false` when `p_ends <= p_starts` (an empty range is contained in every window). Known limit: a session that crosses a window boundary (e.g. 23:30–00:30 at a cafe that closes 00:00 and reopens 00:00) is rejected.
- `get_availability(p_tier_id uuid, p_day date, p_duration_minutes int default 60, p_step_minutes int default 30) returns table (starts_at timestamptz, free_seats int)` — `stable`, `security definer` (it must read `booking_seats`, which the public cannot). For each candidate start from `cafe_open_window` stepping `p_step_minutes` while `start + duration <= upper(window)`, `free_seats` is the count of active stations of the tier with no unreleased seat whose `during` overlaps `[start, start + duration)`, ignoring seats of a lapsed hold (`status = 'held' and hold_expires_at <= now()`), which `create_booking` expires before it allocates, so availability never shows fewer seats than a hold would get. Raises `GG002` for a non-positive `p_duration_minutes` or `p_step_minutes`. Granted to `anon, authenticated`. `p_day` is the opening day in IST. With Friday hours 22:00–02:00 overnight, `get_availability(tier, date '2026-11-20')` returns starts up to Saturday 01:00 IST for a 60-minute duration (window [2026-11-20T16:30Z, 2026-11-20T20:30Z)), and `get_availability(tier, date '2026-11-21')` starts at Saturday's own opening. Returns zero rows, never an error, when the cafe has no `cafe_hours` row for that weekday, when the tier does not exist, or when the cafe is not `live` (so, although it is granted to `anon`, it reveals nothing about draft or paused cafes).
- `create_booking(p_cafe_id uuid, p_tier_id uuid, p_starts_at timestamptz, p_duration_minutes int, p_seat_count int) returns booking_details` — `security definer`, granted to `authenticated` only:
  1. `GG001` if `auth.uid()` is null.
  2. `GG002` unless `30 <= duration <= 360`, `duration % 30 = 0`, `1 <= seats <= 10`, `p_starts_at` is on a 30-minute boundary, `now() + 5 min <= p_starts_at <= now() + 30 days`.
  3. `GG006` unless the cafe is `live` and the tier belongs to it.
  4. `GG003` unless `cafe_is_open_during(cafe, starts, ends)`.
  5. Per-caller caps (`BOOKING_RULES.maxLiveHolds` = 3, `maxUpcomingBookings` = 10 in `@gog/domain` pin the same numbers): `perform pg_advisory_xact_lock(hashtext('booking_user'), hashtext(v_user_id::text));` so two parallel holds by one account cannot both pass the count, then `GG009` ("too many live holds, confirm or cancel one first") when the caller already has 3 rows with `status = 'held' and hold_expires_at > now()`, and `GG009` ("too many upcoming bookings") when the caller already has 10 rows with `starts_at > now()` that are `confirmed` or live `held`. A lapsed hold counts for neither, so nobody waits for the sweeper. Both counts are served by `bookings (user_id, starts_at desc)`; no new index. The user lock is always taken before the tier lock, so the fixed user → tier order cannot deadlock.
  6. `perform pg_advisory_xact_lock(hashtext('station_tier'), hashtext(p_tier_id::text));` — serialises allocation per tier until commit or rollback (take both locks only after the GG001/GG002/GG006/GG003 checks, the user lock first). No `for update skip locked` on `stations`: under Read Committed it neither prevents two near-simultaneous holds from picking the same stations (the second only sees the first's seats after its own snapshot, so the insert fails with `GG005`) nor distinguishes a competitor booking a different hour (which would wrongly produce `GG004`), and it blocks dashboard edits of `stations`.
     - 6a. Lazy expiry for this tier: `with lapsed as (update bookings set status = 'expired' where tier_id = p_tier_id and status = 'held' and hold_expires_at <= now() returning id) update booking_seats set released_at = now() where released_at is null and booking_id in (select id from lapsed);`
     - 6b. In a new statement (plpgsql gives each statement a fresh snapshot, so it sees everything the previous lock holder committed): `select array_agg(id order by label) into v_station_ids from (select s.id, s.label from stations s where s.tier_id = p_tier_id and s.is_active and not exists (select 1 from booking_seats bs where bs.station_id = s.id and bs.released_at is null and bs.during && tstzrange(p_starts_at, v_ends_at, '[)')) order by s.label limit p_seat_count) t;` `GG004` if `coalesce(array_length(v_station_ids, 1), 0) < p_seat_count`.
  7. Insert the booking: `status 'held'`, `hourly_rate_paise`, `tier_name` and `tier_kind` copied from the tier, `cafe_slug` and `cafe_name` copied from the cafe, `total_paise := (round((v_rate::numeric * p_duration_minutes) / 60))::integer * p_seat_count` (numeric rounding, ties away from zero, identical to `Math.round` for non-negative values; integer `/` would truncate and `round(integer)` is a no-op, so an odd-paise rate at 30 minutes would disagree with the TypeScript `quote` by one paise per seat), `hold_expires_at = now() + 10 min`, `source 'app'`. Insert one `booking_seats` row per station with `station_label` copied from the station and `during = tstzrange(starts, ends, '[)')`.
  8. Catch `exclusion_violation` and re-raise as `GG005`. This is the safety net for any writer that does not take the tier lock; under the lock `GG005` should never occur in practice (asserting that with two concurrent pgTAP sessions is out of scope).
  9. `return (select d from booking_details d where d.id = v_id);`

Every status transition is race-safe by construction: `select * into v_booking from bookings where id = p_booking_id for update;` (`GG007` if not found or the caller is not allowed), then the state check (`GG008`), then the update. The `for update` lock means a concurrent transition waits and, when it resumes, sees the updated row and fails the state check. Bulk transitions (`expire_holds`, lazy expiry) are one data-modifying CTE: `with moved as (update bookings … returning id) update booking_seats set released_at = now() where released_at is null and booking_id in (select id from moved)`, so seats are released only for rows this statement actually moved (never the seats of a booking confirmed in between).

- `confirm_booking(p_booking_id uuid) returns booking_details` — `security definer`, `authenticated`. `GG001` if `auth.uid()` is null. `GG007` unless the booking belongs to `auth.uid()`. `GG008` unless `status = 'held'` and `hold_expires_at > now()`. Sets `status = 'confirmed'`, `hold_expires_at = null`. (Later, this is gated by payment.)
- `cancel_booking(p_booking_id uuid) returns booking_details` — `security definer`, `authenticated`. `GG001` if `auth.uid()` is null. Allowed for the booking's user or a `cafe_members` row for its cafe, else `GG007`. `GG008` unless status is `held` or `confirmed`. Sets `status = 'cancelled'` and `released_at = now()` on its unreleased seats.
- `expire_holds() returns integer` — `security definer`, granted to nobody but the owner (called by cron). The same single statement as the lazy expiry in `create_booking`, without the tier filter: `with lapsed as (update bookings set status = 'expired' where status = 'held' and hold_expires_at <= now() returning id), released as (update booking_seats set released_at = now() where released_at is null and booking_id in (select id from lapsed) returning id) select count(*) from lapsed`. Returns the count of `lapsed` rows. (`<=` everywhere a hold lapses; `confirm_booking` requires `hold_expires_at > now()`.)
- `handle_new_user()` trigger function on `auth.users` after insert → `insert into profiles (id, phone)`.
- `set_updated_at()` trigger function.

Cron: pg_cron is a sweeper that keeps `my bookings` tidy; correctness never depends on it because `create_booking` expires lapsed holds for the tier it is about to allocate (so the Homebrew shim, which has no pg_cron, exercises the real flow). `select cron.schedule('expire-holds', '* * * * *', $$select public.expire_holds()$$)` inside a `DO` block that only runs when `pg_cron` is installed.

Immediately after each `create function`, run `revoke execute on function public.<name>(<argument types>) from public, anon, authenticated;` and then grant as stated for that function above (`service_role` keeps its default grant). Do this for every function in this section, including `cafe_open_window`, `cafe_is_open_during`, `handle_new_user`, `set_updated_at` and `expire_holds`: Supabase's initial schema sets `alter default privileges in schema public grant all on functions to postgres, anon, authenticated, service_role`, so every function a migration creates in `public` is granted to `anon` and `authenticated` directly, and `revoke … from public` alone leaves those grants in place (Supabase advisors 0028/0029 flag exactly this). pgTAP 001 asserts `has_function_privilege('anon', 'public.expire_holds()', 'execute')` and `has_function_privilege('authenticated', 'public.expire_holds()', 'execute')` are both false and that `anon` cannot execute `create_booking`. PostgREST exposes only what is granted.

## Row Level Security

Enable on every table. Policies (all `for select` unless stated) are `to anon, authenticated` on the catalog tables and `to authenticated` only on `profiles`, `cafe_members`, `bookings` and `booking_seats` (`anon` can never match `auth.uid()`, and an anon `select` under RLS returns zero rows rather than an error, as test 005 asserts):

| Table                                                      | Policy                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cities`                                                   | `is_live`                                                                                                                                                                                                                                                                                                                                                                             |
| `areas`                                                    | city is live                                                                                                                                                                                                                                                                                                                                                                          |
| `cafes`                                                    | `status = 'live'`                                                                                                                                                                                                                                                                                                                                                                     |
| `cafe_images`, `cafe_hours`, `station_tiers`, `cafe_games` | parent cafe is live                                                                                                                                                                                                                                                                                                                                                                   |
| `stations`                                                 | `is_active` and parent cafe is live                                                                                                                                                                                                                                                                                                                                                   |
| `games`                                                    | all rows                                                                                                                                                                                                                                                                                                                                                                              |
| `promotions`                                               | `is_published`                                                                                                                                                                                                                                                                                                                                                                        |
| `profiles`                                                 | `select` and `update` `to authenticated using (id = (select auth.uid())) with check (id = (select auth.uid()))`; column privileges `revoke update on public.profiles from authenticated; grant update (display_name, home_city_id) on public.profiles to authenticated;` so `phone` and `id` are written only by `handle_new_user()`. No insert policy (trigger only); no delete yet. |
| `cafe_members`                                             | `select` where `user_id = auth.uid()`                                                                                                                                                                                                                                                                                                                                                 |
| `bookings`                                                 | `select` where `user_id = auth.uid()` or a `cafe_members` row exists for `(cafe_id, auth.uid())`. No insert, update or delete policies.                                                                                                                                                                                                                                               |
| `booking_seats`                                            | `select` where the parent booking is visible under the rule above                                                                                                                                                                                                                                                                                                                     |

Use `(select auth.uid())` in policies (Supabase's performance guidance) and keep policies simple enough to read in one breath.

Policies are not the only guard on writes. Supabase's default privileges grant `ALL` on every new table in `public` to `anon` and `authenticated` (the shim mirrors them), RLS never applies to `TRUNCATE`, and a future `create policy … for all` for a partner surface would silently open direct writes that ADR 0011 says happen only through the security-definer functions. Migration `20261104122800_revoke_table_writes.sql` therefore runs `revoke insert, update, delete, truncate, references, trigger on all tables in schema public from anon, authenticated;` and restates `grant update (display_name, home_city_id) on public.profiles to authenticated;` (column privileges survive a table-level revoke). A table created later, in the dashboard or in a migration, receives the default grants again and needs the same revoke; pgTAP 001 asserts the privileges on `bookings` and `profiles`.

## Tests (pgTAP, `supabase test db`)

Each file: `begin; select plan(n); … select * from finish(); rollback;`. Set the caller with `set local role authenticated; select set_config('request.jwt.claims', '{"sub":"<uuid>","role":"authenticated"}', true);` and insert the user into `auth.users` first.

1. `001_schema.sql` — expected tables and enums exist; `btree_gist` exists, and `pg_cron` exists when `pg_available_extensions` lists it; RLS enabled on every table in `public`; the exclusion constraint exists; a `cafe_hours` row `(opens_at 10:00, closes_at 23:00, is_overnight true)` is rejected by the check constraint; the whole function grant matrix as one `select ok(has_function_privilege(r, f, 'execute') = expected) from (values …)`: `anon` and `authenticated` cannot execute `expire_holds`, `cafe_open_window`, `cafe_is_open_during`, `handle_new_user` or `set_updated_at`, only `authenticated` can execute `create_booking`, `confirm_booking` and `cancel_booking`, both can execute `get_availability` and `public` cannot; `authenticated` has neither `truncate` nor `update` on `bookings`, `anon` has no `update` on `profiles`, and `authenticated` keeps the column grant on `profiles.display_name`.
2. `002_exclusion.sql` — two unreleased seats overlapping on one station fail with `exclusion_violation`; adjacent ranges `[10:00, 11:00)` and `[11:00, 12:00)` both succeed; a released seat does not block.
3. `003_create_booking.sql` — as `anon`, `create_booking` fails with `42501` (`throws_ok(..., '42501')`: the function is not granted to `anon`, so permission is denied before the body runs); as `authenticated` with claims `{"role":"authenticated"}` and no `sub`, it fails with `GG001`; invalid duration gets `GG002`; outside hours gets `GG003`; asking for more seats than the tier has gets `GG004`; a valid request returns `held` with the right `total_paise`, `hold_expires_at ≈ now() + 10 min`, and exactly `seat_count` seats; odd-paise rounding is pinned (rate 8025 paise, 30 min, 1 seat → `total_paise` 4013; rate 8025, 90 min, 3 seats → 36114, i.e. 12037.5 → 12038 × 3); a fourth live hold gets `GG009`, cancelling one frees the slot, an eleventh upcoming booking (after confirming holds) gets `GG009` and cancelling one frees that slot too; as a second user (the caps would otherwise interfere) a second booking that would exceed capacity gets `GG004` and a lapsed hold frees its seats for the next caller; as a third user a post-midnight start inside the previous day's overnight window (Pixel Den, Saturday 01:00) is accepted and a session that runs past closing (Side Quest, 23:00 for 60 minutes) gets `GG003`.
4. `004_transitions.sql` — confirm works for the owner, `GG007` for another user, `GG008` after expiry; the owner can cancel a confirmed booking; a member of another cafe gets `GG007`; cancel releases seats so the slot is bookable again; `expire_holds()` expires an old hold and returns 1.
5. `005_rls.sql` — anon sees live cafes and not draft ones; anon sees no `bookings` rows (`is_empty('select * from bookings')`: RLS returns zero rows rather than raising); a user sees only their bookings; a cafe member sees their cafe's bookings; updating `phone` on their own `profiles` row as the owner fails with `42501`.
6. `006_availability.sql` — `get_availability` returns the full station count when empty, one less after a hold, and the right number of slots for an overnight window.

## No-Docker local path (`supabase/local/`)

This machine has Homebrew Postgres 17 and no Docker. For schema work and type generation without Docker:

- `supabase/local/shim.sql` creates the roles `anon`, `authenticated`, `service_role` (nologin) and grants them to the local superuser (`grant anon, authenticated, service_role to current_user`) so `set local role authenticated` works the same way it does under `supabase test db`; schemas `auth` and `extensions`; a minimal `auth.users (id uuid primary key, phone text, email text, created_at)`; and the three auth helpers written out as hosted Supabase defines them today (coalescing the legacy per-claim GUC with the single JSON `request.jwt.claims` GUC that PostgREST ≥ 9 publishes; a shim built from the original `request.jwt.claim.sub`-only definition would fail every RLS and function test). pgTAP tests set only `request.jwt.claims`. The shim does not create `storage` or `pg_cron`; the migrations guard both. The helpers:
  - `create function auth.uid() returns uuid language sql stable as $$ select coalesce(nullif(current_setting('request.jwt.claim.sub', true), ''), (nullif(current_setting('request.jwt.claims', true), '')::jsonb ->> 'sub'))::uuid $$;`
  - `auth.role()` identically with `role` in place of `sub`, returning `text`.
  - `auth.jwt()` = `coalesce(nullif(current_setting('request.jwt.claim', true), ''), nullif(current_setting('request.jwt.claims', true), ''))::jsonb`.
- `scripts/db/local.sh` with subcommands: `up` (initdb into `.local/postgres` if needed, start on port 54329), `reset` (drop and recreate `gog_local`, apply shim, migrations in order, seed), `test` (run the pgTAP files with `pg_prove`, or with `psql` failing on any `not ok`, when the `pgtap` extension is installed; otherwise print how to install it and exit 0), `types` (regenerate `packages/data/src/database.types.ts`), `down`.
- `types` without Docker: Supabase CLI 2.116 runs `gen types` inside a `supabase/postgres-meta:v0.98.0` container even with `--db-url`, so on a machine without a container runtime the script runs the same generator from the root devDependency `@supabase/postgres-meta` 0.98.0 (`node node_modules/@supabase/postgres-meta/dist/server/server.js` with `PG_META_GENERATE_TYPES=typescript`, `PG_META_GENERATE_TYPES_INCLUDED_SCHEMAS=public`, `PG_META_GENERATE_TYPES_DETECT_ONE_TO_ONE_RELATIONSHIPS=true`, the environment the CLI gives its container). The generator formats its output with whichever Prettier it resolves (the repository's here, the image's own in the container), so the raw output differs in formatting between the two; `db:types` and `types` both finish with the repository's Prettier, and the file then comes out the same on every path as long as the npm version matches the image tag the CLI pins. Bump both together when the CLI is upgraded. With Docker on `PATH` the script uses the CLI.
- pgTAP: Homebrew has no `pgtap` formula. Run the SQL tests with Docker (`pnpm db:test`), or build the extension from source against `postgresql@17` (`make PG_CONFIG="$(brew --prefix postgresql@17)/bin/pg_config" && make install`, then `cpanm TAP::Parser::SourceHandler::pgTAP` for `pg_prove`). Until then `pnpm db:local:test` reports the tests as skipped; CI's `supabase test db` is the authoritative run.
- Root scripts: `db:local:up`, `db:local:reset`, `db:local:test`, `db:local:types`, `db:local:down`, next to the Docker-based `db:start`, `db:reset`, `db:test`, `db:types`.

CI uses the real stack (`supabase start`, `supabase test db`, `pnpm db:types`) and fails if the committed `database.types.ts` differs from the regenerated, formatted one.

## `config.toml` edits

`[db] major_version = 17`; `[auth] enable_signup = true`, `[auth.sms] enable_signup = true, enable_confirmations = true`; `[auth.sms.test_otp]` with one test number for local development, written as `919999900001 = "123456"` (digits only: a leading `+` is not a valid bare TOML key, and GoTrue strips the `+` before storing or matching phone numbers, so even a quoted `"+91…"` key would never match); `[auth.sms.twilio] enabled = true` with placeholder values (the CLI disables phone sign-in when no SMS provider is enabled, even for test numbers, which never reach the provider; never `supabase config push` this block to a hosted project); `[db.seed] enabled = true, sql_paths = ["./seed.sql"]`; `site_url` and `additional_redirect_urls` left at defaults for now.

GoTrue stores `auth.users.phone` as digits without `+` (`919999900001`); `handle_new_user()` copies that value into `profiles.phone`. The sign-in screen sends `+91…`; render `+` only at the display edge. `cafes.whatsapp` keeps the `+` form (different column, different check).
